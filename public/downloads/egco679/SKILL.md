# คาบที่ 1 — จากหัวข้อวิจัยสู่ Research Gap

**วันที่:** 19 กันยายน 2569  
**สถานะ:** คาบที่มีหลักฐานยืนยัน

## 1. เลือกหัวข้อให้เป็นงานจริง

อาจารย์ต้องการให้ผู้เรียนเลือกหัวข้อเร็วและคุยกับอาจารย์ที่อาจเป็นที่ปรึกษา หัวข้อไม่จำเป็นต้องเป็น Security เสมอไป แต่ควรมีโอกาสพัฒนาเป็นโครงงานจบได้จริง

ข้อเสนอเริ่มต้นควรตอบ 4 คำถาม:

- **Scope — ขอบเขต:** จะศึกษาอะไร และไม่ศึกษาอะไร
- **Motivation — เหตุผล:** ปัญหานี้สำคัญกับใครหรือระบบใด
- **Objective — เป้าหมาย:** จะทำอะไรให้สำเร็จและตรวจวัดอย่างไร
- **Expected Outcome — ผลที่คาดหวัง:** เมื่อจบแล้วควรได้ข้อมูล วิธี ระบบ หรือตัวชี้วัดอะไร

### เปรียบเทียบแบบง่าย

การเลือกหัวข้อวิจัยเหมือนวางแผนเดินทาง:

- Scope = จะไปถึงที่ไหน ไม่แวะทุกจังหวัด
- Motivation = ทำไมต้องไป
- Objective = วันนี้ต้องเดินทางให้สำเร็จอย่างไร
- Expected Outcome = ถึงปลายทางแล้วต้องมีอะไรเป็นหลักฐาน

หัวข้อกว้างอย่าง “ทำ Security สำหรับ IoT” ยังไม่พอ เพราะยังไม่รู้ว่าอุปกรณ์ชนิดใด ภัยแบบไหน วิธีใด และจะวัดผลอย่างไร

## 2. เริ่ม Literature Review จากแผนที่ใหญ่

อาจารย์แนะนำให้เริ่มจากเปเปอร์ประเภท:

- **Survey:** สำรวจและเปรียบเทียบงานจำนวนมากในหัวข้อเดียว
- **Review:** ทบทวนและวิจารณ์ความรู้หรือวิธีที่มีอยู่
- **Taxonomy:** จัดหมวดหมู่วิธีหรือปัญหาให้เห็นความสัมพันธ์

เปเปอร์เหล่านี้เหมือน “แผนที่ห้าง” ช่วยให้รู้ว่ามีวิธีใดอยู่ชั้นไหน ก่อนเดินเข้าไปอ่านร้านละเอียดย่อยทีละร้าน

สำหรับหัวข้อด้านคอมพิวเตอร์ อาจารย์ขอให้ใช้เปเปอร์ **ปี 2024 เป็นต้นไป** เป็นหลัก เพราะเทคโนโลยีเปลี่ยนเร็ว

เมื่ออ่าน ให้หาอย่างน้อย 4 อย่าง:

1. งานเดิมเปรียบเทียบอะไร
2. แต่ละวิธีมีข้อดี–ข้อเสียอะไร
3. มีข้อจำกัดหรือปัญหาอะไรที่ยังไม่จบ
4. ช่องว่างใดที่หัวข้อของเราพอทำต่อได้

AI, Consensus และเครื่องมือผ่านสิทธิ์มหาวิทยาลัยหรือ ScienceDirect อาจช่วยค้นและจัดโครง แต่ผู้เรียนต้องกลับไปอ่านเปเปอร์จริง เพราะอาจารย์จะถามรายละเอียดเพื่อดูว่าเข้าใจหรือไม่

> ข้อควรระวัง: ชื่อเครื่องมือค้นหลักอีกตัวในเสียงไม่ชัด จึงไม่ควรเดาชื่อจนกว่าจะมีลิงก์ยืนยันจากอาจารย์

## 3. Research Gap คืออะไร

**Research Gap** คือส่วนที่งานเดิมยังตอบไม่ครบ มีข้อจำกัด หรือยังไม่ได้ทดสอบในเงื่อนไขสำคัญ โดยต้องชี้หลักฐานจากเปเปอร์ ไม่ใช่เพียงบอกว่า “เรื่องนี้น่าสนใจ”

รูปประโยคช่วยคิด:

> งานเดิมทำ ______ ได้ดีในเงื่อนไข ______ แต่ยังมีข้อจำกัดเรื่อง ______ ดังนั้นงานนี้จะทดลอง/ออกแบบ ______ และวัดผลด้วย ______

### Gap ที่ยังอ่อน

“ยังไม่มีใครทำระบบนี้”

ปัญหา: อาจเป็นเพราะค้นไม่ครบ หรือไม่มีเหตุผลว่าทำแล้วมีประโยชน์

### Gap ที่แข็งแรงกว่า

“วิธีเดิมให้ความปลอดภัยสูง แต่ใช้พลังงานและหน่วยความจำมากเกินไปสำหรับเซนเซอร์กำลังต่ำ งานนี้จึงจะเปรียบเทียบวิธี lightweight สองกลุ่มภายใต้งบพลังงานเดียวกัน”

จุดแข็ง: บอกวิธีเดิม ข้อจำกัด บริบท วิธีต่อยอด และสิ่งที่จะวัด

## 4. ตัวอย่าง Survey ด้าน Cryptography

อาจารย์ยกตัวอย่างการเปรียบเทียบวิธีหลายกลุ่ม:

- **Symmetric cryptography:** ผู้ส่งและผู้รับใช้กุญแจลับร่วมกัน
- **Asymmetric cryptography:** ใช้คู่กุญแจ public/private
- **Hash:** เปลี่ยนข้อมูลเป็นลายนิ้วมือดิจิทัลเพื่อช่วยตรวจความถูกต้อง
- **OTP:** ในบริบทนี้หมายถึง One-Time Pad ซึ่งใช้กุญแจที่ไม่ใช้ซ้ำและยาวเท่าข้อความ

เกณฑ์ที่ใช้เปรียบเทียบได้:

- **CIA:** Confidentiality (ความลับ), Integrity (ข้อมูลไม่ถูกแก้), Availability (ระบบพร้อมใช้)
- ความแข็งแรงด้านความปลอดภัย
- ความเร็วและทรัพยากรที่ใช้
- ความเหมาะสมกับงานจริง
- ช่องโหว่ที่ทราบแล้ว
- Scalability หรือความสามารถในการขยายระบบ
- การจัดการกุญแจ

### แก่นของตัวอย่าง

ไม่มีวิธีที่ดีที่สุดทุกด้าน ความปลอดภัยที่สูงขึ้นอาจต้องแลกกับเวลา CPU หน่วยความจำ พลังงาน หรือการดูแลระบบ

- **DES และ MD5** ถูกยกเป็นตัวอย่างวิธีเก่าที่มีข้อจำกัดหรือช่องโหว่และมีเหตุผลให้เปลี่ยน
- **Hybrid approach** รวมข้อดีของหลายวิธีได้ แต่เพิ่มความซับซ้อนและค่า maintenance
- Discussion ที่ดีต้องบอกว่าวิธีใดเหมาะกับกรณีใด ไม่ใช่ประกาศผู้ชนะเพียงตัวเดียว

## 5. ตัวอย่าง Cryptography สำหรับ IoT

**IoT** คืออุปกรณ์เชื่อมต่อเครือข่าย เช่น เซนเซอร์ บ้านอัจฉริยะ หรืออุปกรณ์สุขภาพ ปัญหาคือหลายอุปกรณ์มี CPU หน่วยความจำ และพลังงานจำกัด จึงใช้วิธีเข้ารหัสที่หนักเหมือนเซิร์ฟเวอร์ไม่ได้เสมอไป

สิ่งที่ต้องพิจารณา:

- **Lightweight encryption:** การเข้ารหัสที่ออกแบบให้ใช้ทรัพยากรต่ำ
- **Digital signature:** ลายเซ็นดิจิทัลสำหรับยืนยันผู้ส่งและตรวจการแก้ไข
- **Key management:** การสร้าง แจก เก็บ เปลี่ยน และเพิกถอนกุญแจ

ภัยที่กล่าวถึง:

- **Replay:** จับข้อความเก่าแล้วส่งซ้ำเพื่อหลอกระบบ
- **Man-in-the-middle:** ผู้โจมตีแทรกระหว่างการสื่อสาร
- **DDoS:** ส่งคำขอจำนวนมากจนระบบให้บริการไม่ได้

คุณสมบัติความปลอดภัยที่ควรตรวจ:

- Authentication — ยืนยันตัวตน
- Confidentiality — รักษาความลับ
- Integrity — ตรวจว่าข้อมูลไม่ถูกแก้
- Authorization — กำหนดว่าใครทำอะไรได้
- Non-repudiation — ป้องกันการปฏิเสธความรับผิดภายหลัง

บริบทตัวอย่าง ได้แก่ Smart Home, Healthcare, Agriculture, Transport, Energy, Cloud และ Blockchain

### Research Gap ที่คาบนี้ชี้ให้เห็น

- มาตรฐานบางส่วนยังไม่ครบหรือยังเปลี่ยนแปลง
- แนวคิดที่ดูดีในเปเปอร์อาจยังมีช่องว่างเมื่อนำไปใช้จริง
- Infrastructure บางแบบยังมีจุดอ่อน
- วิธี asymmetric หรือมาตรฐานเดิมอาจยังหนักเกินไปสำหรับอุปกรณ์บางชนิด

## 6. รายงานและสไลด์ต้องทำมากกว่าการสรุป

อย่าหยุดที่ “เปเปอร์พูดเรื่องอะไร” ควรตอบต่อว่า:

- ใช้วิธีอะไร
- เปรียบเทียบกับอะไร
- วัดผลด้วยอะไร
- ผลเป็นอย่างไร
- ข้อจำกัดคืออะไร
- เราเห็นด้วยหรือไม่ เพราะอะไร
- จะต่อยอดตรงไหน

ตารางหรือกราฟช่วยให้เห็น trade-off ได้ เช่น เปรียบเทียบ CIA, เวลา, memory, พลังงาน และสถานะมาตรฐาน แต่ทุกช่องต้องมีที่มาจากเปเปอร์ ไม่ใช่คะแนนที่เดาเอง

# คำสำคัญที่ควรจำ

- **Research Topic:** เรื่องหรือปัญหาที่ต้องการศึกษา
- **Scope:** ขอบเขตว่าอะไรอยู่และไม่อยู่ในงาน
- **Motivation:** เหตุผลที่ปัญหานี้ควรถูกแก้
- **Objective:** สิ่งที่งานจะทำให้สำเร็จและวัดได้
- **Expected Outcome:** ผลลัพธ์ที่คาดว่าจะได้เมื่อทำงานเสร็จ
- **Literature Review:** การเชื่อม เปรียบเทียบ และวิจารณ์งานเดิม ไม่ใช่การต่อสรุปหลายเรื่อง
- **Research Gap:** ช่องว่างที่มีหลักฐานว่างานเดิมยังตอบไม่ครบ
- **Trade-off:** ได้ข้อดีด้านหนึ่ง แต่ต้องยอมเสียอีกด้านหนึ่ง
