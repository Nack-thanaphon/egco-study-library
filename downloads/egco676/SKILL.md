# EGCO676 Study Companion

คู่มืออ่านรายวิชา **EGCO676 Network Security and Risk Assessment** แบบเริ่มจากภาพง่ายก่อนศัพท์เทคนิค ใช้ทบทวน 4 คาบแรก เตรียมสอบ และติวกับ AI ได้

> เส้นเรื่องทั้งวิชา: รู้ว่าต้องปกป้องอะไร → เลือกเครื่องมือให้ตรงเป้าหมาย → ดูแลกุญแจและความเชื่อถือให้ปลอดภัย

## ใช้ไฟล์นี้เมื่อใด

- ทบทวนว่าแต่ละคาบเรียนอะไร
- แยก Encryption, Hash, MAC, Signature และ PKI ให้ไม่สับสน
- เตรียมตอบคำถามเชิงเปรียบเทียบ
- ฝึกอธิบายศัพท์ Security ด้วยภาษาของตัวเอง
- ขอให้ AI ถามทีละข้อและช่วยชี้จุดที่ยังไม่เข้าใจ

## แผนที่ใหญ่ก่อนเริ่ม

ลองนึกถึงการส่งกล่องเอกสารสำคัญ:

1. **Encryption** = ใส่กล่องล็อก เพื่อไม่ให้คนอื่นอ่าน
2. **Hash** = ทำลายนิ้วมือของเอกสาร เพื่อตรวจว่าเนื้อหาเปลี่ยนไหม
3. **MAC** = ทำลายนิ้วมือร่วมกับรหัสลับที่สองฝ่ายรู้ เพื่อเช็กทั้งการแก้ไขและผู้ส่งในกลุ่มที่แชร์กุญแจ
4. **Digital Signature** = เจ้าของใช้กุญแจส่วนตัวเซ็น ทุกคนใช้กุญแจสาธารณะตรวจได้
5. **Certificate** = บัตรรับรองว่ากุญแจสาธารณะนี้เป็นของใคร
6. **PKI** = ระบบทั้งหมดที่ออก ตรวจ ต่ออายุ และยกเลิกบัตรรับรองเหล่านั้น

เครื่องมือแต่ละชิ้นตอบคนละคำถาม จึงใช้แทนกันไม่ได้ทั้งหมด

## ตารางแยก 5 แนวคิดที่มักสับสน

| แนวคิด | คำถามที่ตอบ | ใช้กุญแจไหม | ให้ความลับไหม | ยืนยันผู้ส่งไหม | ย้อนกลับเป็นข้อมูลเดิมได้ไหม |
|---|---|---|---|---|---|
| **Encryption** | คนอื่นอ่านข้อมูลได้ไหม | ใช้ | ได้ | ไม่ได้โดยอัตโนมัติ | ได้เมื่อมีกุญแจถอด |
| **Hash** | ข้อมูลเปลี่ยนไหม | ไม่ใช้ | ไม่ได้ | ไม่ได้ | ไม่ควรย้อนกลับได้ |
| **MAC** | ข้อมูลเปลี่ยนไหม และมาจากผู้ถือ Secret key หรือไม่ | Secret key ร่วมกัน | ไม่ได้ | ได้ในกลุ่มที่แชร์กุญแจ | ไม่ใช่การถอดข้อมูล |
| **Digital Signature** | ใครเซ็น และข้อมูลเปลี่ยนไหม | Private/Public key | ไม่ได้ | ได้ พร้อมช่วยเรื่อง Non-repudiation | ไม่ใช่การถอดข้อมูล |
| **PKI** | เราเชื่อได้อย่างไรว่า Public key เป็นของคนนั้นจริง | จัดการกุญแจและ Certificate | ไม่ได้ด้วยตัวมันเอง | ช่วยสร้างความเชื่อถือในตัวตน | ไม่ใช่อัลกอริทึมแปลงข้อมูล |

### ประโยคจำง่าย

- **อยากซ่อนข้อความ → Encryption**
- **อยากรู้ว่าข้อความเปลี่ยนไหม → Hash**
- **อยากรู้ว่ามาจากคนในกลุ่มที่ถือกุญแจร่วมกันไหม → MAC**
- **อยากให้เจ้าของเซ็นและคนทั่วไปตรวจได้ → Digital Signature**
- **อยากรู้ว่า Public key เป็นของใคร → Certificate และ PKI**

## คาบที่ 1 — Introduction, CIA และ Risk

**วันที่:** 15 สิงหาคม 2569

### เรียนอะไร

- **Confidentiality:** คนไม่มีสิทธิ์อ่านข้อมูลไม่ได้
- **Integrity:** ข้อมูลไม่ถูกเปลี่ยนโดยไม่รู้ตัว
- **Availability:** ระบบพร้อมใช้เมื่อจำเป็น
- Authentication, Authorization, Accountability/Auditing และ Non-repudiation
- Threat, Vulnerability, Risk และ Countermeasure
- Defense in Depth และการลด Attack Surface

### อธิบายแบบง่าย

ใช้ Mobile Banking เป็นภาพจำ:

- คนอื่นดูยอดไม่ได้ = **Confidentiality**
- คนอื่นเปลี่ยนเลขบัญชีไม่ได้ = **Integrity**
- เราโอนได้เมื่อต้องใช้ = **Availability**
- ระบบรู้ว่าเราเป็นเจ้าของบัญชีจริง = **Authentication**
- ระบบจำกัดว่าเราทำอะไรได้ = **Authorization**
- ระบบมีบันทึกว่าใครทำอะไร = **Accountability**

### Threat, Vulnerability และ Risk ต่างกันอย่างไร

สมมติบ้านมีหน้าต่างที่ปิดไม่สนิท:

- **Threat** = ขโมยที่อาจเข้าบ้าน
- **Vulnerability** = หน้าต่างที่ปิดไม่สนิท
- **Risk** = โอกาสและความเสียหายหากขโมยใช้หน้าต่างนั้น
- **Countermeasure** = ซ่อมหน้าต่าง ติดกลอน หรือเพิ่มสัญญาณเตือน

มีขโมยอยู่ไม่ได้แปลว่าทุกบ้านเสี่ยงเท่ากัน และมีหน้าต่างเสียก็ไม่ได้แปลว่าจะเกิดเหตุแน่นอน ต้องดูทั้งโอกาสและผลกระทบ

### สิ่งที่อาจารย์เน้น

- ป้องกันหลายชั้น อย่าฝากระบบไว้กับด่านเดียว
- ความปลอดภัยต้องสมดุลกับการใช้งานจริง
- Key Management สำคัญพอ ๆ กับการเลือกอัลกอริทึม
- ตารางและกำหนดการอาจเปลี่ยน ให้ตรวจประกาศล่าสุดใน Google Classroom

## คาบที่ 2 — Symmetric Cryptography

**วันที่:** 22 สิงหาคม 2569

### แนวคิดหลัก

Symmetric Encryption ใช้ **กุญแจลับดอกเดียวกัน** สำหรับเข้ารหัสและถอดรหัส

- `C = E(K, P)` หมายถึงนำ Plaintext `P` กับ Key `K` ไปเข้ารหัส ได้ Ciphertext `C`
- `P = D(K, C)` หมายถึงนำ Ciphertext `C` กับ Key `K` ไปถอด ได้ข้อความเดิม `P`

ข้อดีคือเร็ว เหมาะกับข้อมูลจำนวนมาก ข้อเสียคือจะแจกกุญแจลับให้ผู้รับโดยไม่รั่วได้อย่างไร

### แบบจำลองการโจมตี 4 แบบ

1. **Ciphertext-only:** ผู้โจมตีเห็นเพียงข้อความที่เข้ารหัส
2. **Known-plaintext:** ผู้โจมตีรู้คู่ข้อความเดิมกับข้อความเข้ารหัสบางส่วน
3. **Chosen-plaintext:** ผู้โจมตีเลือกข้อความเดิมให้ระบบเข้ารหัสได้
4. **Chosen-ciphertext:** ผู้โจมตีเลือกข้อความเข้ารหัสให้ระบบลองถอดได้

ยิ่งผู้โจมตีควบคุมสิ่งที่ป้อนให้ระบบได้มาก การทดสอบความแข็งแรงก็ยิ่งเข้มขึ้น

### DES ไป AES

- **DES:** กุญแจ 56 บิต สั้นเกินไปสำหรับปัจจุบัน
- **Double DES:** ถูกลดความแข็งแรงด้วย meet-in-the-middle
- **3DES:** แข็งแรงขึ้นแต่ช้าและเป็นเทคโนโลยีเก่า
- **AES:** มาตรฐานสมัยใหม่ ใช้กุญแจ 128, 192 หรือ 256 บิต

### Modes of Operation

- **ECB:** บล็อกเดิมให้ผลเดิม จึงเห็น pattern ซ้ำ ไม่เหมาะกับข้อมูลที่มีรูปแบบ
- **CBC:** แต่ละบล็อกผูกกับบล็อกก่อนหน้า ช่วยซ่อน pattern แต่ทำงานตามลำดับ
- **CTR:** ใช้ counter สร้างค่าที่ต่างกัน ทำงานขนานได้และ error ไม่กระจายไปบล็อกอื่น
- **CFB/OFB:** เปลี่ยน block cipher ให้ทำงานคล้าย stream แต่พฤติกรรมการส่งต่อค่าและ error ต่างกัน

จำว่า “ใช้ AES” ยังตอบไม่ครบ ต้องบอกด้วยว่าใช้ **mode ใด** และจัดการ nonce/IV อย่างไร

## คาบที่ 3 — Asymmetric, Hybrid และ Post-Quantum

**วันที่:** 29 สิงหาคม 2569

### กุญแจสองดอก

- **Public key:** แจกให้คนอื่นได้
- **Private key:** เจ้าของต้องเก็บเป็นความลับ

ภาพจำคือตู้ไปรษณีย์: ทุกคนหยอดจดหมายผ่านช่องได้ แต่เจ้าของเท่านั้นที่มีกุญแจเปิดตู้

### Encryption กับ Signature ใช้กุญแจคนละทิศ

- ต้องการส่งความลับให้ผู้รับ: ใช้ **Public key ของผู้รับ** เข้ารหัส ผู้รับใช้ Private key ถอด
- ต้องการเซ็นว่าเราส่งจริง: ใช้ **Private key ของผู้ส่ง** เซ็น คนอื่นใช้ Public key ของผู้ส่งตรวจ

อย่าจำเพียงว่า “สลับกุญแจ” ให้ถามก่อนว่าเป้าหมายคือ **ซ่อนข้อมูล** หรือ **ยืนยันผู้ส่ง**

### Hybrid Encryption

ระบบจริงมักใช้สองแบบร่วมกัน:

1. ใช้ Asymmetric แลกหรือส่ง **Session key**
2. ใช้ Symmetric เข้ารหัสข้อมูลจริงตลอด session

เหตุผลคือ Asymmetric ช่วยเรื่องแจกกุญแจ ส่วน Symmetric เร็วกว่ามาก

### Post-Quantum

Shor algorithm ทำให้ปัญหาที่ RSA, Diffie–Hellman และ ECC พึ่งพาอ่อนแอลงเมื่อมีคอมพิวเตอร์ควอนตัมขนาดใหญ่พอ

ความเสี่ยงแบบ **Harvest now, decrypt later** คือผู้โจมตีเก็บ Ciphertext วันนี้ แล้วรอเทคโนโลยีพร้อมจึงถอดในอนาคต ข้อมูลที่ต้องลับนานจึงต้องวางแผนเปลี่ยนระบบล่วงหน้า

แนวทางที่เรียน ได้แก่ lattice-based, code-based และ hash-based signature ส่วน Symmetric ยังรับมือได้ด้วยขนาดกุญแจที่เหมาะสม

## คาบที่ 4 — Hash, MAC, Signature, Key Management และ PKI

**วันที่:** 5 กันยายน 2569

### Hash

Hash รับข้อมูลยาวเท่าไรก็ได้ แล้วให้ **digest ขนาดคงที่** เปลี่ยนข้อมูลเล็กน้อย ผลควรเปลี่ยนมาก

คุณสมบัติสำคัญ:

- **Preimage resistance:** เห็น digest แล้วหาข้อความต้นฉบับยาก
- **Second-preimage resistance:** มีข้อความหนึ่งแล้ว หาข้อความอื่นที่ได้ digest เดียวกันยาก
- **Collision resistance:** หาข้อความสองชุดใด ๆ ที่ได้ digest เดียวกันยาก

MD5 และ SHA-1 มีปัญหา collision แล้ว เนื้อหาในคาบแนะนำอย่างต่ำ SHA-256 หรือ SHA-3

### MDC, MAC และ Signature

- **MDC/Hash:** ตรวจ Integrity ไม่มี key
- **MAC:** ใช้ Secret key ร่วมกัน ให้ Integrity + Authentication ภายในกลุ่มผู้ถือกุญแจ
- **Digital Signature:** เจ้าของใช้ Private key เซ็น ทุกคนใช้ Public key ตรวจ ให้ Integrity + Authentication + Non-repudiation

Signature มักเซ็น **digest** ไม่ใช่ข้อความทั้งก้อน เพราะ digest เล็กและขนาดคงที่

### KDC และ Kerberos

**KDC** เป็นศูนย์กลางช่วยแจก Session key ให้คู่สื่อสาร โดยห่อกุญแจด้วยกุญแจที่แต่ละฝ่ายมีกับ KDC

Kerberos ใช้ภาพ “หมา 3 หัว”:

1. **AS** ตรวจตัวตน
2. **TGS** ออก Ticket
3. **Real Server** ให้บริการ

### Certificate และ PKI

การประกาศ Public key เองยังไม่พอ เพราะคนร้ายอาจสลับกุญแจ

- **CA** ออกและเซ็น Certificate มาตรฐาน X.509
- **Certificate** ผูกชื่อเจ้าของกับ Public key และช่วงเวลาที่ใช้ได้
- **Chain of Trust** เชื่อม Certificate ไปยัง Root CA ที่เครื่องเชื่อถือ
- **PKI** รวม CA, RA, Repository, ผู้ใช้ นโยบาย และวงจรชีวิตกุญแจ

วงจรชีวิตไม่ได้จบที่สร้างกุญแจ ต้องมีติดตั้ง ใช้ สำรอง กู้คืน อัปเดต ยกเลิก และทำลาย

4. แยก “เนื้อหาจากคาบ” ออกจาก “ความรู้เสริม” ให้ชัด
5. ไม่แต่งตัวเลข กำหนดการ หรือคำพูดของอาจารย์ที่ไม่มีในเอกสาร
6. หากผู้เรียนสับสน ให้กลับไปถาม 4 ช่อง: เป้าหมายคืออะไร ใช้กุญแจอะไร ได้ผลลัพธ์อะไร และอะไรที่เครื่องมือนี้ไม่ให้
7. เมื่อผู้เรียนตอบผิด ให้บอกจุดผิดสั้น ๆ แล้วให้ลองใหม่ก่อนเฉลยเต็ม

## จุดที่ต้องตอบได้ก่อนจบ

- CIA แต่ละด้านต่างกันอย่างไร
- Threat, Vulnerability และ Risk เชื่อมกันอย่างไร
- Symmetric กับ Asymmetric ต่างกันที่จำนวนกุญแจ ความเร็ว และการแจกกุญแจอย่างไร
- เหตุใดระบบจริงจึงใช้ Hybrid Encryption
- Encryption ต่างจาก Hash อย่างไร
- Hash ต่างจาก MAC อย่างไร
- MAC ต่างจาก Digital Signature อย่างไร
- Certificate และ PKI ช่วยแก้ปัญหา Public key ถูกสลับอย่างไร
- เหตุใด RSA, Diffie–Hellman และ ECC ต้องเตรียมเปลี่ยนในยุค Quantum
